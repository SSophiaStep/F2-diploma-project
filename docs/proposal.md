# Thesis Proposal

## 1. Робоча назва проєкту

**UA:** BlindBudget — платформа приватного бенчмаркінгу особистих фінансів студентів на основі протоколу Secure Aggregation

**EN:** BlindBudget — Privacy-Preserving Peer Spending Benchmark Platform for Students

## 2. Актуальність та проблематика

Студенту корисно розуміти, чи його витрати по категоріях (їжа, транспорт, розваги) відповідають типовим витратам однолітків — це допомагає скоригувати особистий бюджет без суб'єктивних орієнтирів. Наявні застосунки особистих фінансів або взагалі не пропонують порівняння з групою (показують лише індивідуальну статистику користувача), або публікують непрозорі загальні середні показники без пояснення джерела й методу обчислення.

Технічна складність задачі: пряме порівняння вимагає передачі індивідуальних фінансових даних на єдиний сервер для агрегації, що є неприйнятним порушенням приватності — фінансові дані є чутливою категорією персональної інформації, а централізоване зберігання створює єдину точку витоку для всіх учасників групи. Водночас агрегований результат (середнє, медіана по групі) має зберігати коректність обчислення без розкриття жодного індивідуального значення.

## 3. Сформована ідея продукту

**Тип системи:** розподілена система на основі криптографічного протоколу Secure Aggregation (протокол приватного підсумовування значень між учасниками без розкриття окремих значень координуючому серверу), що обчислює агреговану статистику витрат групи студентів без доступу жодної зі сторін до індивідуальних фінансових даних інших учасників.

Архітектура складається з клієнтських застосунків (мобільний додаток студента), сервісу-координатора раундів агрегації та сервісу формування і показу результатів порівняння.

## 4. Детальний опис функціоналу (Core Features)

1. **Клієнтське маскування даних** — кожен клієнт перед відправкою суми витрат по категорії генерує узгоджені попарно з іншими учасниками групи випадкові маски так, щоб сума всіх масок дорівнювала нулю при підсумовуванні на сервері.
2. **Сервіс-координатор раундів агрегації** — керує life-cycle кожного раунду збору даних (реєстрація учасників, збір замаскованих значень, обробка підсумку), не маючи доступу до жодного окремого значення.
3. **Обробка відключення учасників (dropout handling)** — якщо частина клієнтів виходить з мережі посеред раунду, сервіс відновлює коректну суму лише за даними учасників, що завершили раунд, використовуючи механізм розподілення секрету (secret sharing) масок для компенсації відсутніх.
4. **Контроль k-анонімності** — результат порівняння показується лише за умови, що кількість учасників групи перевищує заданий поріг (наприклад, 20), інакше запит на порівняння відхиляється.
5. **Шар диференційної приватності** — додавання контрольованого шуму до фінального агрегату як другий рівень захисту від атак реконструкції індивідуальних значень.
6. **Формування сегментів порівняння** — групування учасників за критеріями (заклад освіти, курс, місто) без розкриття списку учасників групи клієнту.
7. **Дашборд порівняння для користувача** — візуалізація позиції власних витрат відносно агрегованих показників групи (перцентиль, відхилення від медіани) по категоріях.

## 5. Попередній інструментарій та технологічний стек

### Мови програмування
Python (backend-сервіси, криптографічне ядро), TypeScript/React Native (мобільний клієнт).

### Архітектурні патерни
Secure Multi-Party Computation (Secure Aggregation Protocol), Round-based Distributed Protocol, Coordinator Pattern, Secret Sharing (для відновлення при відключенні учасників), BFF для клієнтського дашборду.

### Фреймворки та бібліотеки
FastAPI (сервіс-координатор, API), PySyft (примітиви Secure Aggregation), PyCryptodome (Secret Sharing, криптографічні операції), React Native (мобільний клієнт).

### Бази даних
PostgreSQL (метадані раундів агрегації, конфігурація груп), Redis (тимчасове зберігання стану раунду, черги учасників).

### DevOps та інструменти якості
Docker (контейнеризація сервісів), GitHub Actions (CI/CD), pytest (тестування коректності протоколу агрегації на синтетичних даних), k6 (навантажувальне тестування координатора при великій кількості учасників раунду).
